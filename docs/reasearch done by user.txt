## The 4 Modules You Build

### Module A — Conversational History Engine
- Patient speaks naturally: *"Mujhe 3 din se seenay mein dard hai"*
- AI follows clinical frameworks (SOCRATES / OLDCARTS)
- Asks follow-ups: *"Dard kahan se shuru hota hai? Kya radiation hoti hai?"*
- Dual-mode: voice OR tap (for low-literacy users)
- **Red-flag detection**: chest pain + dyspnoea → instant priority alert to triage

### Module B — Document Digitisation & Intelligence
- Patient scans old prescriptions, lab reports, discharge summaries
- OCR (printed + handwritten, multilingual)
- AI extracts: diagnoses, medications + dosages, lab values + reference ranges
- Auto-organises into chronological timeline
- Flags abnormal lab values and potential drug interactions

### Module C — Structured Summary Generator
- AI synthesises voice history + scanned documents into ONE physician-ready summary
- Standard format: Chief Complaint → HPI → Past History → Drug/Allergy → Family → Personal → ROS
- Bilingual output (patient gets audio confirmation in local language; doctor gets English/Hindi text)
- Doctor edits/confirms before saving — AI never diagnoses autonomously

### Module D — ABDM Integration
- Patient authenticates via ABHA ID
- Structured history pushed to Hospital HIS via FHIR APIs
- Links to Ayushman Bharat Digital Mission ecosystem
- Consent-first design (audio-guided consent for low-literacy patients)

### The "First-Mile" Problem

"First mile" is a logistics term — the *first step of getting something into the system* (first mile = pickup from sender; last mile = delivery to your door).

In healthcare, before any record can flow through ABDM, **it must first exist in digital form.** But look at the reality of an Indian patient:

- Their history lives **in their head** — *"do hafte se khaansi hai."*
- Their past records are **paper** — handwritten prescriptions and lab reports in a plastic bag.

None of that is inside the ABDM ecosystem. And there is **no patient-facing tool** that captures it *before* the consultation. Existing hospital software only captures name, age, token number — zero clinical data.

So: **the highway is built, but there is no on-ramp at the patient's end.** The data never enters the system, and the doctor wastes his 2 minutes extracting it manually.

**UPI analogy:** ABDM is the UPI rails that move money between banks. ABHA is your VPA. FHIR is the protocol. But UPI only works because you have a *phone app* to initiate the transaction. In health, that "app" — the tool that captures and injects data at the source — **is missing.**

*Tagline: "The ATM moment for Indian hospital OPDs." / "Giving every Indian doctor the 2 minutes they never had."*

MediKiosk is a self-service clinical intake kiosk where the patient **speaks** their history in their own language (AI conversational interview), **scans** their old papers (OCR + entity extraction), and the system generates a **structured, physician-ready, FHIR-compliant summary** pushed to the HIS and linked to ABHA — all *before* the patient enters the consultation room. The physician reads a complete history in seconds and spends the full 2 minutes on examination, reasoning and counselling.

1. Robust Indian-language **ASR** (Bhashini / AI4Bharat IndicWhisper)
2. **LLMs** for conversational clinical history elicitation
3. High-accuracy **OCR** for handwritten + printed medical documents
4. **ABDM FHIR** interoperability rails
*None coexisted before ~2023. The window is open now.*

## 1.5 Innovation Hooks (Differentiators)
| Hook | What it is |
|------|-----------|
| **Continuity Engine** | Gap-adaptive re-interview: system computes days since last visit; <30d asks only delta questions, 30–90d delta + ROS review, >90d near-full interview. Never re-asks what it knows. |
| **Consent as Row-Level Security** | Consent is not a UI checkbox — enforced in Postgres RLS. A doctor literally cannot read a summary without an active consent row. DPDP 2023 by design. |
| **FHIR-Native Output** | Every summary exports as an HL7 FHIR R4 Bundle (Patient/Condition/Observation/MedicationStatement/DocumentReference/Composition). |
| **Dashavidha Decision Tree** | First solution to encode Ayurvedic Pariksha parameters as a voice-driven ontology — the moat that scares away competitors. |
| **Medication Safety Split** | "The AI never prescribes. It prepares." Patient sees only current-med list + reminders; doctor gets AI medication review (interactions, duplicates, lab correlations). |
| **Immutable Audit (ALCOA+)** | Doctor may amend the draft; raw AI extraction + patient submissions are append-only, never editable/deletable. |

## 1.6 Target Users
Rural/elderly/low-literacy patients • Returning patients • OPD physicians (Allopathy + AYUSH) • Triage staff • Hospital ABDM/ABHA officers.

## 5.3 Data Model (Supabase SQL)
```sql
create table users (id uuid primary key references auth.users,
  role text check (role in ('patient','doctor')), abha_id text, language text);
create table visits (id uuid primary key default gen_random_uuid(),
  patient_id uuid references users, visit_date timestamptz default now(),
  gap_days int, interview_type text check (interview_type in ('full','delta')));
create table consents (id uuid primary key, visit_id uuid references visits,
  granted_to uuid references users, active boolean default true);
create table documents (id uuid primary key, visit_id uuid references visits,
  file_path text, ocr_json jsonb, entities_json jsonb);
create table summaries (id uuid primary key, visit_id uuid references visits,
  draft_json jsonb, fhir_bundle jsonb,
  status text default 'draft' check (status in ('draft','approved','amended')));
create table suggestions (id uuid primary key, summary_id uuid references summaries,
  type text check (type in ('redflag','interaction','abnormal_lab')),
  text text, confidence float, cited_source text);
create table audit_log (id bigint generated always as identity,
  actor uuid, action text, target uuid, ts timestamptz default now());

alter table summaries enable row level security;
create policy doctor_consented_read on summaries for select
using (exists (select 1 from consents c
  where c.visit_id = summaries.visit_id
    and c.granted_to = auth.uid() and c.active = true));
revoke update, delete on audit_log from authenticated;  -- ALCOA+ immutability
```

## 5.5 AI Pipeline & Ontology
**Pipeline:** Mic → Bhashini ASR → Dialogue Manager (ontology-constrained Llama) → TTS reply → (parallel) Scan → PaddleOCR → LLM entity extraction → Summarizer → FHIR builder → Realtime push.
**Ontology config (JSON, extensible):**

```json
{
 "allopathy": {"chest_pain": {"framework":"SOCRATES",
   "probes":["site","onset","character","radiation","associated_symptoms",
             "time_course","exacerbating_relieving","severity_1_10"],
   "redflags":["dyspnoea","diaphoresis","syncope"]}},

   "satmya","sattva","ahara_shakti","vyayama_shakti","vaya"],
   "ahara_vihara":["diet_pattern","sleep","exercise","routine"]}
}
```
**Prompt guardrails:** extract/summarize ONLY; never diagnose; abstain on uncertainty; cite sources for suggestions.
